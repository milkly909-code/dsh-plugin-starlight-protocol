# 方案：侧边栏分组折叠（Sidebar Groups）

> 状态：**待确认**（确认后才进入开发）
> 目标插件包：`dsh-plugin-sidebar-groups`（暂定名）
> 适用版本：DSH Desktop 0.2.2-rc.3（当前运行版本，已实测勘察）

---

## 1. 需求理解

你给的截图只截到侧栏上半部分，内容是「插件 / 插件市场 / 自动化任务 / 上下文洞察 / GitHub / 学习工作台 / 热榜 / 更多」这一列。

结合你的原话「侧边栏附件截图分为一类，可以折叠，工作区分为一类，可以折叠」，我理解为：

**把侧边栏竖向内容拆成两个可折叠分组：**

```
┌ 侧边栏 ─────────────────────┐
│  🐋  Logo / 新会话            │   ← 宿主固定区，不动
│                              │
│  ▾ 面板                       │   ← 新增：分组头 1（可折叠）
│      插件                     │
│      插件市场                  │
│      自动化任务                 │
│      上下文洞察                 │
│      GitHub                   │
│      学习工作台                 │
│      热榜                     │
│      更多                     │
│                              │
│  ▾ 工作区          🔍 ＋ ⋯     │   ← 分组头 2（复用宿主段头，前面加折叠箭头）
│      工作区 A                  │
│      └ 会话 …                  │
│      工作区 B                  │
│                              │
│  ⚙ 设置                       │   ← 宿主固定区，不动
└──────────────────────────────┘
```

- 两个分组**互相独立**折叠，折叠状态各自记忆。
- 「更多」属于面板分组，一起折叠。
- 分组折叠只是"收起显示"，**不影响**插件注册、不影响面板 id、不影响会话与工作区数据。

---

## 2. 勘察结论（决定方案形态的关键事实）

用 `Slots.listSubTree` 拉取了完整的实时 Slot 树，并读了 `dsh-client-ui-sidebar`、`dsh-client-ui-workspace`、`dsh-client-ui-layout` 的源码，得到三条硬事实：

1. **宿主侧栏是 `sidebar` 单槽（single）**，唯一占用者是 ui-sidebar 的 `SidebarRoot`。它内部结构固定为：logo 行 → 新会话行 → **滚动视口**（里面是 `nav` 面板列表 + `sidebar.workspaces` 区域）→ 底部操作/设置。
2. **`nav` 面板列表与工作区区域之间没有任何插槽位**。可用的侧栏插槽只有：`sidebar.brand.mark`、`sidebar.brand.name`、`sidebar.toggle.badge`、`sidebar.panellist`（每个面板行的**图标**）、`sidebar.panellist.actions`（"更多"菜单里的行）、`sidebar.workspaces`（整块，已被 ui-workspace 占用）、`sidebar.settings`、`sidebar.footer.action`、`sidebar.session.action`（只包"新会话"行的 HOC）。**没有一个位置能在面板列表上方插入一行分组头。**
3. 宿主为集成方预留了**稳定标记**（官方 README 明确写了"供测试和集成方定位"）：
   - `[data-sidebar-scrollport]` — 侧栏滚动视口
   - `[data-sidebar-workspace-header]` — 工作区段头
   - `[data-sidebar-list-area]` — 工作区列表滚动容器
   - `[data-sidebar-collapsed]` — 侧栏处于 56px 收起态（在 AppFrame 上）

**结论：不存在纯 Slots 组合就能实现"两组折叠"的插入点。** 只有两条现实路径（见 §3）。

## 3. 方案对比

| | 方案 A：注入式增强（推荐） | 方案 B：接管 `sidebar` 单槽 |
|---|---|---|
| 做法 | Client 插件用 MutationObserver + `styles.insert()`，在宿主 `nav` 首位插入面板分组头、在工作区段头左侧插入折叠箭头，靠 CSS 类切换折叠 | 注册自己的 `sidebar` 占用者，**整个侧栏**（品牌行、新会话、抽屉、收起动画、滚动接力、底部设置）自己重写一遍，再按你的要求分组 |
| 改动量 | 小（~600–900 行，含样式与自愈逻辑） | 大（需复刻 SidebarRoot 的 500 行 + 22KB CSS + 滚动接力逻辑） |
| 与宿主升级的关系 | 依赖 4 个 data 标记（官方声明稳定），标记消失时插件**自动降级为无操作**，不会坏掉侧栏 | 每次 DSH 升级都可能要跟着改，且会遮蔽官方侧栏 UI |
| 风险 | 属于"给宿主 DOM 打补丁"；React 重渲染可能挪动我插入的节点 → 用观察器自愈 | 单槽是"遮蔽式"覆盖：官方侧栏的动画、抽屉、macOS/Windows 标题栏细节全要自己重做；子插槽声明可能与官方条目冲突 |
| 卸载影响 | 移除注入节点与样式即完全还原 | 卸载即回到官方侧栏 |

**推荐方案 A。** 理由：这是本项目（外观插件工作区）一贯的做法（`starlight-protocol` 的 `SidebarToggleManager` 就是同思路），且功能面小、可完全回退；而方案 B 相当于把宿主最复杂的组件之一抄一遍，升级维护成本远超收益。

> 如果你更在意"绝不碰宿主 DOM"，那只能选 B，我会把工作量与升级风险在开工前再单独列一份清单给你。

## 4. 方案 A 详细设计

### 4.1 注入点（只增不改）

| 分组 | 注入位置 | 增 | 改 |
|---|---|---|---|
| 面板分组 | `[data-sidebar-scrollport] nav` 的**第一个子节点** | 一行「▾ 面板」按钮（36px 高，样式对齐宿主段头） | 折叠时给 `nav` 加 `dsh-sg-collapsed` 类，其余子元素 `display:none` |
| 工作区分组 | `[data-sidebar-workspace-header]` 的**第一个子节点** | 一个 16px 折叠箭头按钮（宿主自己的「工作区」文字就是组名，不重复造标签） | 折叠时给 `[data-sidebar-list-area]` 加 `dsh-sg-collapsed`，列表隐藏；**段头保留**，搜索/添加工作区按钮永远可用 |

- 不移动、不删除宿主任何节点，只插入和加 class。
- 面板分组头的文字用局部字典（中/英/日…跟随 `ctx.locale`），工作区分组沿用宿主自己的标签（`工作区` / `会话`，在"平铺"视图下自动变成「会话」，无需我处理）。

### 4.2 交互

- **点击分组头整行**（面板组）/ **点击箭头或组名**（工作区组）→ 折叠 / 展开。
- 折叠动画：高度 + 透明度 150ms `--ds-ease-in-out`，与宿主折叠侧栏的节奏一致；`prefers-reduced-motion` 下直接切换。
- 键盘：都是原生 `<button>`；`aria-expanded` + `aria-controls` 指向对应容器；Enter/Space 原生可用；`:focus-visible` 用宿主 focus ring 令牌。
- 收起态（56px 轨道 / Windows 标题栏折叠态）：两组的分组头**自动隐藏**，行为与现状完全一致。
- 抽屉态（窄窗口）：正常显示，可折叠。

### 4.3 状态与持久化

- 2 个布尔值：`panels` / `workspaces`，默认**都展开**。
- 存 `localStorage`：`dsh-sidebar-groups/v1`，键名带版本号，读写失败静默降级（隐私模式/配额满不影响侧栏）。
- 额外提供「恢复默认」入口（初始版本可只放在设置项里，见 4.5）。

### 4.4 自愈（应对 React 重渲染）

- 用 `MutationObserver` 观察 `[data-sidebar-scrollport]` 子树（`childList` + `subtree`，`attributes` 只盯 `class`）。
- 回调里做幂等三件事：① 分组头在首位 → 不在就 `insertBefore` 回来；② 箭头挂在段头首位 → 丢了就补；③ 折叠类被 React 冲掉 → 重新加上。用 `requestAnimationFrame` 合并，避免抖动。
- 插件 dispose 时：断开观察器、移除插入节点、移除 `<style>`、移除加的 class —— 侧栏 100% 还原。

### 4.5 样式与主题

- 只用主题令牌：`--dsw-alias-label-primary/secondary/tertiary`、`--dsw-alias-interactive-bg-hover`、`--dsw-radius-md`，并能继承侧栏自己的 `--dsh-sidebar-row-padding` / `--dsh-sidebar-paint-inset`（这些自定义属性在侧栏根节点上，会自然级联到我插入的节点）。
- 深浅色自适应；不写死颜色。
- 视觉参数对齐宿主：行高 36px、左内距 `--dsh-sidebar-row-padding`、悬停圆角 `--dsw-radius-md`、字号 12px + 字重 500（比面板行 14px 略弱，形成层级）。

### 4.6 可选增强（默认不做，确认后加）

- 分组头右侧显示数量徽标（如「面板 7」）。
- 设置页加一组开关：默认折叠状态、是否记忆、是否显示徽标。
- 折叠时把分组头做成吸附（sticky）在视口顶部。

## 5. 交付物与验收

**交付物**
```
01-外观插件/dsh-plugin-sidebar-groups/
├── package.json          # dsh.bundle.patch + dsh.client(platform: web)
├── cordis.patch.yml
├── index.js              # Host 半边（空 apply，仅占位）
├── client.js             # Client 半边：注入 / 折叠 / 持久化 / 自愈
├── locale/{zh,en}.json   # meta.title / meta.description / 界面文案
├── icon.svg              # 原创图标
├── docs/DETAIL.md + preview.svg
└── test/check.mjs        # 离线断言：注入幂等、类名切换、状态读写、清理还原
```

**验收标准**
1. 侧栏出现两个可折叠分组，互不影响；「更多」跟随面板组折叠。
2. 折叠状态刷新页面、重启 DSH 后保持。
3. 56px 收起态不出现分组头，展开回来状态不丢。
4. 新增/移除插件、切换工作区、搜索会话后，分组头与折叠状态不被打乱（自愈）。
5. 深浅色主题下观感与宿主一致，无写死颜色。
6. 停用/卸载插件后侧栏完全恢复原样，控制台无残留报错。
7. 独立验证 + 一轮 UI/UX 复核（`references/verification.md` 要求）。

**已知限制（会写进 `meta.description`）**
- 依赖宿主的 4 个 `data-` 标记；官方若改名，插件降级为"不生效"而不会破坏侧栏。
- 属于 DOM 增强，官方侧栏若大改结构，可能需要小版本适配。
